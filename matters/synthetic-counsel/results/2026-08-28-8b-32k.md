# Qwen3-8B Q5_K_M at 32k context on work M5 Pro (24 GB)

Date: 2026-08-28. One full 40-question batch through the real `ask.ask()`
pipeline (retrieval + two-key gate + prompt + number check + attribution
check + audit), streaming path. Purpose: confirm the 8B is safe at a 32,768
context window (raised from the 8,192 used in the temp sweeps), and re-score
the current test set. Scored by hand against ANSWER-KEY.md.

## Configuration

- Machine: work M5 Pro, 24 GB unified. Model: `qwen3-8b` (unsloth
  Qwen3-8B-GGUF, Q5_K_M) via LM Studio 127.0.0.1:1234.
- Embedder: `text-embedding-nomic-embed-text-v1.5@q8_0` (hybrid RRF, W_DENSE 0.5).
- Load: context **32,768** (was 8,192); Flash Attention ON; KV cache Q8_0;
  all 36 layers GPU; thinking OFF; Repeat Penalty OFF; Max Concurrent 1.
- Request (ask.py GEN): temp 0.0, top_p 0.80, presence 1.5, max_tokens 1200.
- Harness: top_k 5, min_score 1.0, dense_min 0.5; Q17/Q18 use `--diverse --top-k 8`.

## 32k context is safe

- Highest per-answer context use was 3% of 32,768. No truncation, no
  late-chat gibberish, server log confirms `n_ctx_slot = 32768`.
- Terse, cited output; 1.0 min wall-clock for the whole batch.
- Conclusion: keep the 8B at 32k. Long real documents will no longer
  truncate, and short questions are unaffected.

## Q16 regression (the only mover vs the 8B temp-0 sweep)

The temp-0 8B sweep at 8k scored 39/40 with Q35 the sole miss, so Q16 was a
clean "No" there. At 32k, Q16 degraded:

- The model derived the right conclusion: "Firm Delta did not provide a
  response... no reply from Firm Delta is documented" (cites S1, S2).
- It then appended "**Answer:** Not specified in the sources." The delivered
  bottom line is a refusal, which is wrong for an answerable question.

Likely cause: Q16 is borderline for the 8B (it also failed at temp 0.1 in the
sweep). The only real change is context 8,192 -> 32,768, which shifts the
attention numerics enough to flip a greedy pick on a marginal question. This
is NOT truncation; the answer used 1% of the window.

## Q17 / Q18 improved

Both aggregate questions passed. `--diverse --top-k 8` pulled Alpha (S6) and
Bravo (S7) into the slots. This is the coverage case that failed on the M3 8B
run (Q17 omitted Alpha; Q18 missed the Bravo amount).

## Notes for the scoring protocol

1. The batch counter hid Q16. The summary reads "answered 31, refused 9",
   but Q16's bottom line refuses. The classifier only checks whether the
   answer STARTS with "Not specified"; Q16 starts with reasoning. A real
   scorer must catch a refusal phrase that appears at the END too.
2. The 4 number warnings are all Q16 date-in-heading noise (08, 12, 19,
   2026), not fabrication. Known `verify_numbers` behavior (reads body, not
   headings).
